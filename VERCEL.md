# Vercel + постоянный игровой сервер

Клиент готов для публикации на Vercel. Комнаты, личные ключи, карточки и состояние стола хранятся постоянным Node.js-сервером. Можно запускать его на вашем Windows-ПК через СТАРТ-ИНТЕРНЕТ.bat или отдельно на сервере с постоянным диском. Полностью автономное серверное развёртывание на Vercel этим комплектом не реализовано.

## Через исходный репозиторий

1. Загрузите содержимое проекта в свой Git-репозиторий, исключив `data`, `tools`, `node_modules`, архивы и файлы с секретами. Игровые сохранения и личные ключи нельзя публиковать.
2. Импортируйте репозиторий в Vercel. Оставьте Root Directory корнем проекта: `vercel.json` содержит установку, сборку, выходную папку и маршрутизацию `/room/...`.
3. Добавьте Environment Variable **VITE_SERVER_URL**: публичный HTTPS-адрес работающего игрового сервера без завершающего `/`. Например, домен вашего туннеля. Это публичный адрес, не пароль и не ключ.
4. Deploy. Создавайте комнаты и приглашайте участников с адреса Vercel: тогда браузерное сохранение привязано к постоянному домену клиента.
5. На сервере задайте **CLIENT_ORIGINS=https://ваш-проект.vercel.app**. Несколько точных адресов разделяются запятой. Локальный клиент с того же адреса сервера работает и без CORS.

Альтернатива: импортировать только папку `client`, выбрать Vite, Build Command `npm run build`, Output Directory `dist`. Внутри неё уже есть отдельный `vercel.json`. Файл `.env.example` — образец; на Vercel переменную задают через настройки проекта.

При изменении VITE_SERVER_URL нужна новая сборка/Deploy, поскольку Vite подставляет его при сборке. Бесплатный туннель может менять домен: для постоянной игры удобнее стабильный домен серверной части. Пока сервер на ПК, компьютер и туннель должны быть включены. Смена серверного адреса с сохранением той же папки `data` и того же домена клиента сохраняет участников и партии.

## Сохранения

`localStorage` браузера сохраняет личность отдельно для каждой комнаты и резервную копию карт. Сервер хранит комнаты в `data/rooms-v1.json`, личный ключ на сервере записан только как SHA-256. После обновления страницы клиент возвращает то же место; отключение ведущего не передаёт роль другому. Роль можно передать вручную прежней кнопкой.

При перезапуске сервера сохраняются участники, ведущий, карты, свечи, кости и замок. Свечи продолжают отсчёт реального времени. Не удаляйте папку `data`; не запускайте два процесса сервера с одной папкой данных. Пользовательские записки — содержимое карт персонажа и остальных карт — сохраняются вместе с ними.

В другом браузере, приватном режиме, после удаления данных сайта или на другом домене автоматический вход не переносится. Это личное место в комнате, не регистрация по почте. Старые версии до 1.1.0 не записывали сессии: восстановить уже потерянную старую учётку автоматически невозможно. Обновляйтесь между партиями.

## Граница проверки

Сборка Vercel-клиента и CORS проверяются локально. Публикация в вашем аккаунте Vercel требует вашего проекта и адреса серверной части; в аккаунт ничего автоматически не загружено.

Официальная документация: https://vercel.com/docs/frameworks/frontend/vite . Vercel теперь документирует WebSocket в Functions (https://vercel.com/kb/guide/do-vercel-serverless-functions-support-websocket-connections), но для переноса этой серверной части туда нужны отдельное общее постоянное хранилище и согласование состояния экземпляров. Здесь выбран проверяемый вариант с постоянным сервером.
